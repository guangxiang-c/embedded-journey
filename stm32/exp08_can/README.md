# exp08 - STM32F407 bxCAN 与 USB-CAN 分析仪双向通信

> 状态：✅ 已打通并多轮验证（2026-10-27）。
> STM32F407（CAN1 与 CAN2 两组引脚均验证通过）↔ SN65HVD230 ↔ USB-CAN-A ↔ PC，
> 500kbps / 1Mbps 双向收发，计数器数据逐秒递增，错误计数器全 0。

## 一、成果

- 串口端：持续收到 PC 经 USB-CAN-A 发来的帧（`Rx ID:200 len:8 data:0 17 34 51`）
- 上位机端：持续收到板子发出的帧（`接受 0x131 01 02 03 04 05 06 07 08`，首字节逐秒 +1）
- 总线状态：正常，错误计数器全 0
- 覆盖验证：CAN1（PA11/PA12）与 CAN2（PB12/PB13）两套引脚、500k 与 1M 两种速率、
两组不同的位时序参数组合

## 二、硬件与接线图（最终验证版）

```javascript
┌─────────────────┐         ┌──────────────────────┐         ┌─────────────────┐
│   STM32F407      │  杜邦线  │  微雪 SN65HVD230      │  导线    │   微雪 USB-CAN-A │
│   最小系统板       │────────→│  CAN Board           │────────→│                 │
│                  │         │                      │         │                 │
│  CAN1: PA11(RX) ─┼────────→│ 排针 CAN RX (RXD输出)  │         │                 │
│  CAN1: PA12(TX) ─┼────────→│ 排针 CAN TX (TXD输入)  │         │                 │
│  (或 CAN2: PB12/PB13，同名相接)│                      │         │                 │
│  JP1 3.3V ──────┼────────→│ 排针 3.3V            │         │                 │
│  JP1 GND ───────┼────────→│ 排针 GND             │         │                 │
│                  │         │                      │         │                 │
│                  │         │ 端子 CANH ──────────┼────────→│ 端子 CAN-H       │
│                  │         │ 端子 CANL ──────────┼────────→│ 端子 CAN-L       │
│                  │         │                      │         │ 端子 GND ←──────┼── 共地线
└─────────────────┘         └──────────────────────┘         └────────┬────────┘
        │                                                           │
        │  USB(UART, CH340)                                           │ USB
        ↓                                                           ↓
     串口助手 XCOM                                              USBCAN V2.12 上位机
     (COM9, 115200)                                          (COM6, 串口2M / CAN 500K或1M)
```

接线四要点：

1. **同名相接**：模块丝印按"数据流向"命名（CAN RX = 交给 MCU 的数据脚），RX 对 RX、TX 对 TX，不按引脚功能交叉
2. **CANH 对 CANH、CANL 对 CANL**：丝印顺序与直觉可能相反，接反 = 反极性差分 = 全静默（本工程最大坑）
3. **必须第三根 GND** 共地
4. **两个 120Ω 在物理两端**（模块板载 R2 + USB-CAN-A 拨码 ON），中间节点不加

## 三、关键配置

### 500kbps（APB1 = 42MHz）

两套等价组合都验证通过：

```c
// 组合 A：N=12，采样点 ~71%
Prescaler = 7;      // HAL 字段 = 分频数本身（HAL 内部 -1 存入寄存器）
BS1 = CAN_BS1_6TQ;  // N = 1+6+5 = 12，42M ÷ 7 ÷ 12 = 500k
BS2 = CAN_BS2_5TQ;

// 组合 B：N=7，采样点 ~71%
Prescaler = 12;
BS1 = CAN_BS1_4TQ;  // N = 1+4+2 = 7，42M ÷ 12 ÷ 7 = 500k
BS2 = CAN_BS2_2TQ;
```

### 1Mbps

```c
Prescaler = 6;      // 42M ÷ 6 ÷ 7 = 1M
BS1 = CAN_BS1_4TQ;  // N = 7
BS2 = CAN_BS2_2TQ;
```

通用公式：`波特率 = 42MHz ÷ Prescaler ÷ (1 + BS1 + BS2)`，约束：BS1 ≥ BS2、采样点 67%~87%、Prescaler 使结果落在目标值。

### 滤波器（全收）

| 控制器 | 可用组号 | 本工程 |
| --- | --- | --- |
| CAN1 | 0 ~ 13 | FilterNumber = 0 |
| CAN2 | 14 ~ 27 | FilterNumber = 14 |

掩码全 0 = 全收。**组号挂错控制器 = 单向通信**（发送不经过滤波器，接收必过）。

### 其他

```c
Mode = CAN_MODE_NORMAL;
ABOM = ENABLE;     // Bus-Off 自动恢复
NART 调试期 ENABLE（禁止自动重发），量产建议 DISABLE
```

## 四、故障复盘：多层叠加故障（首次调通历程）

| # | 故障 | 现象 | 修复 |
| --- | --- | --- | --- |
| ① | 波特率 545k（Prescaler=11 被当作 ÷12） | 与分析仪速率失配 | Prescaler=12 |
| ② | CANH/CANL 端子接反 | 反极性差分，全静默 | 端子两根线对调 |
| ③ | 模块排针 TX/RX 交叉 | 控制器收不到收发器 | 同名相接 |
| ④ | DLC 越界（把计数器当长度传入 >8） | 非法帧 → 错误风暴 → Bus-Off | 计数器入数据字节，长度恒 8 |

**核心教训：多故障叠加时互相掩盖，每修复一个，之前所有排除结论作废重来。**

## 六、排障方法论（实战记录）

1. 多故障叠加时，每修复一个 bug，之前所有排除项作废重验
2. 回环模式通过 ≠ TX 引脚有输出 ≠ 波特率正确（回环无视位时序）
3. 逻辑分析仪（3.3V 阈值）看不见 CAN_H（2.5~3.5V 永不跨阈值），"H 平线"是仪器盲区
4. 万用表平均值法测占空比信号：把信号密度拉高（去延时连续发）让 0.1V 级变化可读
5. 寄存器遥测（MSR/TSR/ESR/BTR）比波形更诚实；位编码（LEC）必须查手册原文
6. 共享总线上的单点波形只能说明"有人在发"，不能归因于谁
7. 注释会骗人（ST 官方例程的速率注释都是错的），以计算和测量为准
8. DLC、ID、滤波器组号等协议字段都有法定范围，越界不是"多带数据"而是"制造总线垃圾"

## 七、常用判读速查

| 遥测/测量 | 含义 |
| --- | --- |
| LEC=5 | 位显性错：发了显性、读到隐性 → 信号没上总线（接线/收发/极性） |
| LEC=3 | ACK 错：帧完整发出，无人应答 |
| LEC=4 | 位隐性错：发了隐性、读到显性 → 总线被外力强拉显性 |
| TEC/REC 上涨 | 发送/接收错误累积，定位错误方向 |
| TSR 邮箱空 + TERR | 在尝试发送但以错误收场 |
| MSR INAK=1 / SLAK=1 | 卡在初始化模式 / 睡眠模式 |
| CANH-CANL ≈ 60Ω | 两个 120Ω 终端都在岗 |
| 寄存器字段值 | 实际值 = 读出值 + 1（从 0 数数原则） |
