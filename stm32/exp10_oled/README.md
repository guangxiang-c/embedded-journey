# exp10 - I2C 总线实战：OLED 显示 + AHT20 温湿度（一主多从）

> 状态：? 完成（2026-10-28）。一条 I2C2 总线（PB10/PB11）挂两个从机，
> OLED（0x3C）显示三行实时数据：温度、湿度、PWM 呼吸值。捂手测试数据真实响应。

## 一、成果

- OLED 第 0/1/2 行分别显示 `T:25.3C` / `H:58.2%` / `CMP:300`，1 秒刷新
- AHT20 温湿度传感器与 OLED 共享 I2C 总线（地址 0x38 / 0x3C，互不冲突）
- 呼吸灯（PWM）不受显示/采样阻塞，任务各用各的节拍
- 验收：捂手 10 秒，温度 +4℃、湿度 +9%，数据真实响应物理世界

## 二、硬件与接线

| 器件 | 地址 | 接线 |
| --- | --- | --- |
| 0.96" OLED（SSD1306，4 针） | 0x3C | VCC-GND-SCL-SDA（注意：该模块 VCC 在 1 脚，非 GND 打头） |
| AHT20 温湿度模块（4 针） | 0x38 | VIN-GND-SCL-SDA（供电脚叫 VIN，接 3.3V） |

两模块并联在同一组 SCL/SDA 上（面包板做接线排）；AHT20 排针未焊，
用面包板免焊按压法接触。

```javascript
STM32 PB10(I2C2_SCL) ──┬──→ OLED SCL ──→ AHT20 SCL
STM32 PB11(I2C2_SDA) ──┴──→ OLED SDA ──→ AHT20 SDA
3.3V / GND ── 整块面包板电源轨
```

## 三、关键配置与代码结构

- I2C2：PB10/PB11，AF4，**开漏模式 + 上拉**（I2C 器件只拉低不推高，靠上拉电阻抬线）
- 400kHz 快速模式
- `oled.c`：I2C 初始化 / SSD1306 初始化序列（电荷泵 0x8D 0x14 是关键）/
双页写入 `oled_show_char`（8×16 字占 16 行 = 连续两页）
- AHT20：发触发命令 0xAC 0x33 0x00 → 等 80ms → 收 6 字节 → 20 位原始值定点换算
（`temp_x10 = raw*2000/1048576 - 500`，避开浮点）

## 四、今天踩过的坑（按遇见顺序）

| # | 坑 | 教训 |
| --- | --- | --- |
| 1 | OLED 模块 VCC 在 1 脚（非常规序） | 接线前必读丝印，不接"常识" |
| 2 | 板载 OLED 座是 FPC 排线座，4 针模块插不上 | 查实物再定方案；备选 PB10/PB11 飞线反而更适合教学 |
| 3 | `OLED_ADDR` 宏定义在 .c 里，main.c 引用报未定义 | 跨文件共享的宏必须放 .h |
| 4 | 8×16 字体一次性写 17 字节 → 字上下错位 | 8×16 占 2 页，必须分两次写 |
| 5 | 变长数字用"擦除+重写"刷新 → 残影（99 变 990）且闪烁 | **定宽格式化（%3d）全量覆盖**：无擦除、无残影、无闪烁 |
| 6 | OLED 的 100ms 等待直接放主循环 → 呼吸灯慢 10 倍 | 多任务各用各的节拍（HAL_GetTick 软件门控） |
| 7 | 串口 printf 中文字符 → ARMClang 编码警告 | 串口输出一律英文 |

## 五、概念清单（I2C 一课毕业）

- 上拉电阻与"线与"：谁都能拉低、没人推高、空闲靠电阻抬
- ACK 机制：每个字节后跟 1 位应答——比 UART 可靠的核心
- 起始/停止条件：SCL 高时 SDA 的下降沿/上升沿
- 一主多从：7 位地址点名，0x3C 与 0x38 同总线共存
- 定点数换算：嵌入式避免 float 的正统做法
- 调试三神器用法：ACK 扫描（`HAL_I2C_IsDeviceReady`）定位物理层、
逻辑分析仪看时序、万用表量上拉
